Verification

Check the code.
Then test the biology.

The repository includes numerical tests, input validation checks and an independent Python reference.

These checks examine the software’s behavior and numerical agreement. They do not establish clinical accuracy, biological validity or improved research decisions.

The release documentation records its test commands and browser checks. Use the commands and environment details when reproducing a result.

Data & limitations

Know what
you are looking at.

Reported evidence and a separate sandbox.

The first view presents reported study summaries. The separate regional sandbox starts with 82 invented region identifiers and 30 invented reference maps. Its synthetic arrays do not reproduce either study or supply missing anatomical values.

Imports need a known correspondence.

The software checks a supported input structure. You still need to verify data permissions, matching region IDs, order and anatomical alignment. A valid file is not proof of a valid scientific comparison.

The model does not estimate cell function.

Substrate, gain, thresholds, noise and time are model assumptions. They are not fitted patient biology. The regional sandbox computes descriptive associations without spatial-null significance testing. The separate study-evidence view preserves the testing reported in each source.

Reproducibility needs the input too.

Keep the permitted input bundle alongside the evidence report, source revision and commands. The exported report does not contain raw input arrays and cannot by itself reproduce an imported comparison.

The Life Sciences challenge

What would
distinguish the states?

The challenge asks how to distinguish adaptation or compensation from loss of function.

Our contribution is an original conditional simulation, an interface for examining it, and a comparison of hypothetical measurements. The scientific research that motivates it predates the event.
